# COOL COOL CLUB ระบบจัดคิวสนามแบด

เวอร์ชันมีเซิร์ฟเวอร์และฐานข้อมูลจริง (Node.js + SQLite) เจ้าหน้าที่หลายเครื่องใช้ข้อมูลชุดเดียวกัน และผู้เล่นเปิดดูคิวสดบนมือถือได้

| ลิงก์ | ใช้ทำอะไร | ต้องใส่ PIN |
|---|---|---|
| `https://โดเมนของคุณ/` | บอร์ดคิวสำหรับผู้เล่น ดูอย่างเดียว ค้นหาชื่อตัวเองเพื่อดูลำดับคิว | ไม่ต้อง |
| `https://โดเมนของคุณ/staff` | หน้าเจ้าหน้าที่ จัดคิว ลากคนลงคอร์ท จบเกม เก็บเงิน ดูประวัติ | ต้อง |

บอร์ดของผู้เล่นแสดงเฉพาะชื่อ ระดับ คอร์ท และเวลารอ ไม่แสดงยอดเงิน จำนวนลูก หรือสถานะจ่ายเงิน

## สิ่งที่ต้องมี

- เครื่องเซิร์ฟเวอร์ที่รัน **Node.js 22 ขึ้นไป** หรือ **Docker** (VPS ราคาเริ่มประมาณ 150 ถึง 300 บาทต่อเดือนก็พอ)
- **พื้นที่เก็บไฟล์ถาวร** สำหรับไฟล์ฐานข้อมูล (`data/club.db`) ถ้าโฮสต์ล้างไฟล์ทุกครั้งที่รีสตาร์ต ข้อมูลจะหาย
- โดเมนหรือซับโดเมน (เช่น `queue.coolcoolclub.com`) และ HTTPS

รันได้เพียง **1 อินสแตนซ์** ต่อ 1 ฐานข้อมูล ซึ่งเพียงพอสำหรับสนามแบดทั่วไป

## เริ่มใช้งานเร็วที่สุด (Docker)

```bash
cp .env.example .env        # แล้วแก้ STAFF_PIN เป็นรหัสของคุณ
docker compose up -d --build
```

เปิด `http://IP-ของเครื่อง:3000/staff` ใส่ PIN แล้วใช้งานได้เลย ข้อมูลอยู่ในโฟลเดอร์ `./data`

## เริ่มโดยไม่ใช้ Docker

```bash
npm ci --omit=dev
STAFF_PIN=รหัสของคุณ npm start
```

## ทำให้เป็น HTTPS บนโดเมนของคลับ

วิธีง่ายที่สุดคือใช้ Caddy (ขอใบรับรอง HTTPS ให้อัตโนมัติ) ชี้ DNS ของโดเมนมาที่เครื่องนี้ก่อน แล้วรัน

```bash
caddy reverse-proxy --from queue.โดเมนของคุณ.com --to localhost:3000
```

หรือใส่ไฟล์ `Caddyfile` ตามตัวอย่างใน `Caddyfile.example` แล้วรันเป็นบริการถาวร ถ้าใช้ Nginx ให้ตั้ง reverse proxy ไปที่พอร์ต 3000 และปิด buffering ของเส้นทาง `/api/events` (`proxy_buffering off;`) เพื่อให้อัปเดตสดทำงาน

### ถ้าจะใช้ผู้ให้บริการแบบ Platform (Railway, Render, Fly.io ฯลฯ)

ต้องผูก **Persistent Volume/Disk** ไปที่โฟลเดอร์ `/app/data` (หรือตั้ง `DB_PATH` ให้ชี้ไปที่ดิสก์ถาวร) ไม่อย่างนั้นข้อมูลจะหายเมื่อรีสตาร์ตหรืออัปเดต และตั้ง `TRUST_PROXY=1`

## ตัวแปรค่า (ไฟล์ `.env`)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `STAFF_PIN` | ไม่มี (บังคับ) | รหัสเข้าหน้าเจ้าหน้าที่ อย่างน้อย 4 ตัวอักษร เปลี่ยนรหัสโดยแก้ค่านี้แล้วรีสตาร์ต |
| `PORT` | 3000 | พอร์ต |
| `CLUB_NAME` | COOL COOL CLUB | ชื่อคลับบนบอร์ดผู้เล่น |
| `TZ_NAME` | Asia/Bangkok | เขตเวลาสำหรับวันที่ของประวัติรายวัน |
| `TOKEN_DAYS` | 30 | อายุการล็อกอินของเจ้าหน้าที่ (วัน) |
| `SESSION_SECRET` | สร้างเองและเก็บในฐานข้อมูล | กุญแจเซ็นโทเคน |
| `TRUST_PROXY` | 1 | ใช้ 1 เมื่อรันหลัง Caddy/Nginx ใช้ 0 ถ้าเปิดพอร์ตตรง |
| `DB_PATH` | `./data/club.db` | ที่เก็บไฟล์ฐานข้อมูล |

## การใช้งานประจำวัน

1. เจ้าหน้าที่เปิด `/staff` ใส่ PIN (จำไว้ในเครื่อง 30 วัน) เครื่องไหนก็ได้ ข้อมูลตรงกันทุกเครื่อง มีป้าย "ซิงค์แล้ว" ที่มุมบนบอกสถานะ
2. ส่งลิงก์ `/` ให้ผู้เล่นดูคิว หรือเปิดขึ้นจอทีวีที่สนาม
3. คนที่เคยมาแล้ว: แท็บ **ผู้เล่น → สมาชิกทั้งหมด** ค้นชื่อแล้วกด **เช็กอิน** ไม่ต้องพิมพ์ชื่อใหม่ทุกครั้ง ระบบจำระดับมือ เบอร์โทร และยอดค้างจ่ายให้อัตโนมัติ
4. คนใหม่: แท็บ **ผู้เล่น → วันนี้** พิมพ์ชื่อ เลือกระดับ กด **เพิ่ม** (ช่อง "บันทึกเป็นสมาชิกคลับ" ติ๊กอยู่แล้ว ระบบจะจำไว้ให้เจอกันครั้งหน้า)
5. ปิดวัน: แท็บ **ตั้งค่า** กด **เริ่มวันใหม่** ระบบบันทึกยอดเงิน รายชื่อ และประวัติทุกเกมของวันนั้นลงฐานข้อมูลก่อน แล้วค่อยล้างจำนวนเกม (รายชื่อสมาชิกไม่หาย ยังเช็กอินพรุ่งนี้ได้) ถ้าบันทึกไม่สำเร็จจะไม่ล้างข้อมูล
6. ดูย้อนหลัง: แท็บ **หลังบ้าน** เลื่อนลงไปที่ "ประวัติรายวัน" กดวันที่เพื่อดูรายละเอียด ติ๊ก "จ่ายแล้ว" ย้อนหลังได้ถ้าเก็บเงินไม่ทันตอนนั้น และดาวน์โหลด CSV เปิดใน Excel ได้

## ข้อมูลสมาชิก (ทะเบียนถาวร)

ระบบแยก "คนบนกระดานวันนี้" กับ "ทะเบียนสมาชิกถาวร" ออกจากกัน ทะเบียนสมาชิกเก็บชื่อ ระดับมือ เบอร์โทร (ถ้าใส่) และยอดใช้จ่ายสะสม เพื่อให้เช็กอินคนหน้าเดิมได้เร็วและตามยอดค้างจ่ายได้ แท็บ **ผู้เล่น → สมาชิกทั้งหมด**:

- **ค้นหา** พิมพ์ชื่อหรือเบอร์โทรบางส่วนก็เจอ
- **แก้ไข** กดที่ชื่อ เพื่อแก้ชื่อ ระดับ เบอร์โทร หมายเหตุ และดูประวัติการมาเล่นของคนนั้น
- **ซ่อน** สำหรับคนที่เลิกเล่นแล้ว แต่ยังไม่อยากลบประวัติเงิน กดกู้คืนได้ภายหลัง
- **ลบข้อมูลถาวร** ใช้เมื่อเจ้าของข้อมูลขอให้ลบ (ตามสิทธิ PDPA) ระบบลบชื่อ เบอร์โทร และหมายเหตุออกจากทุกที่ทันที ยอดเงินในประวัติวันนั้นยังอยู่ (จำเป็นสำหรับบัญชี/ภาษี) แต่ชื่อจะถูกแทนที่ด้วย "(ลบข้อมูลแล้ว)" และกู้คืนไม่ได้
- **นำเข้ารายชื่อ** วางรายชื่อหลายคนพร้อมกัน รูปแบบ `ชื่อ,ระดับ,เบอร์โทร` บรรทัดละคน (ระดับและเบอร์ใส่หรือไม่ใส่ก็ได้) เหมาะกับการย้ายรายชื่อจากที่เก่า
- **ส่งออก CSV** ดาวน์โหลดรายชื่อสมาชิกพร้อมสถิติทั้งหมด

บอร์ดผู้เล่น (`/`) ที่เปิดสาธารณะ **ไม่เชื่อมกับทะเบียนสมาชิก** และไม่แสดงเบอร์โทรหรือยอดเงินของใครทั้งสิ้น แสดงเฉพาะชื่อ ระดับ และคิวของคนที่เช็กอินไว้ในวันนั้นเท่านั้น

## สำรองข้อมูล

- **อัตโนมัติ**: เซิร์ฟเวอร์สำรองฐานข้อมูลทั้งหมดให้เองทุก 30 นาทีที่มีการเปลี่ยนแปลง เก็บไว้ในโฟลเดอร์ `data/backups/` ย้อนหลัง 14 วัน (ปรับด้วย `BACKUP_KEEP`) ดูวันเวลาที่สำรองล่าสุดได้ที่แท็บตั้งค่า
- **ดาวน์โหลดเอง**: แท็บตั้งค่า ปุ่ม **สำรองข้อมูล** ดาวน์โหลดไฟล์ `.db` เก็บไว้ที่อื่นเป็นระยะ (เช่น Google Drive) เผื่อเครื่องเซิร์ฟเวอร์มีปัญหา

## ข้อควรรู้

- **การแก้พร้อมกัน**: ถ้าสองเครื่องแก้ในเวลาเกือบเดียวกัน เครื่องที่บันทึกช้ากว่าจะโหลดข้อมูลล่าสุดแทนและมีข้อความแจ้ง แล้วทำซ้ำอีกครั้ง
- **ออฟไลน์**: ถ้าเน็ตหลุดระหว่างใช้งาน แอปยังใช้ต่อได้และจะส่งขึ้นเซิร์ฟเวอร์เมื่อเน็ตกลับมา (ถ้าไม่มีใครแก้ระหว่างนั้น) ถ้าเปิดหน้าเว็บขณะออฟไลน์ ต้องรอเน็ตกลับมาก่อนจึงซิงค์
- **ความปลอดภัย**: มีรหัส PIN เดียวสำหรับเจ้าหน้าที่ทุกคน ใส่ผิดเกิน 10 ครั้งจะถูกหน่วงไว้ 10 นาที ต้องใช้ผ่าน HTTPS เสมอ บอร์ดผู้เล่นเปิดสาธารณะและเห็นชื่อผู้เล่นที่เช็กอินวันนั้น (ไม่เห็นเบอร์โทรหรือเงิน) ถ้าไม่ต้องการให้คนนอกเห็นแม้แค่ชื่อ อย่าเผยแพร่ลิงก์บอร์ด
- **ข้อมูลส่วนบุคคล (PDPA)**: เก็บเท่าที่จำเป็น (ชื่อ ระดับมือ เบอร์โทรถ้าใส่) ไม่มีที่อยู่หรือเลขบัตรประชาชน ควรมีนโยบายแจ้งลูกค้าว่าเก็บข้อมูลเพื่อจัดคิวและตามยอดค้างจ่าย และใช้ปุ่ม "ลบข้อมูลถาวร" เมื่อลูกค้าขอให้ลบ
- ถ้าต้องการรหัสแยกสิทธิ์ (เช่น เฉพาะเจ้าของดูยอดเงินได้) ต้องพัฒนาเพิ่ม

## โครงสร้างสำหรับผู้พัฒนา

```
server.js            Express + SQLite (better-sqlite3), SSE, ล็อกอินด้วย PIN + โทเคนเซ็น HMAC
public/board.html    บอร์ดผู้เล่น (สาธารณะ)
public/staff.html    แอปเจ้าหน้าที่ (ไฟล์เดียว, ซิงค์กับเซิร์ฟเวอร์)
test/api.test.js     ชุดทดสอบ API   รัน: npm test
```

ตาราง SQLite: `live_state` (สถานะสดของคิว เป็น JSON พร้อมเลขเวอร์ชัน), `members` (ทะเบียนสมาชิกถาวร), `sessions`, `session_players`, `session_games` (ประวัติรายวัน, ผูกกับ `members` ผ่าน `member_id`), `meta`

API หลัก (ต้องมีโทเคนจากการล็อกอิน ยกเว้นที่ระบุว่าสาธารณะ)

- `POST /api/login` แลก PIN เป็นโทเคน (สาธารณะ)
- `GET/PUT /api/state` สถานะสดของกระดานวันนี้ PUT ต้องส่ง `baseVersion` ถ้าไม่ตรงได้ 409 พร้อมข้อมูลล่าสุด
- `GET /api/events` SSE แจ้งเลขเวอร์ชันใหม่ (สาธารณะ) / `GET /api/version` (สาธารณะ) / `GET /api/board` ข้อมูลบอร์ดผู้เล่น ไม่มีเงิน (สาธารณะ)
- `GET /api/members`, `POST /api/members/ensure`, `POST /api/members/bulk`, `GET/PUT /api/members/:id`, `DELETE /api/members/:id` (`?permanent=1` ลบถาวร), `GET /api/members.csv`
- `PUT /api/session-players/:id` แก้สถานะจ่ายเงินของแถวในประวัติย้อนหลัง
- `POST /api/archive`, `GET /api/sessions`, `GET /api/sessions/:id`, `GET /api/sessions/:id/csv`
- `GET /api/backup` ดาวน์โหลดไฟล์ฐานข้อมูลทันที, `GET /api/backup/status` ดูเวลาไฟล์สำรองอัตโนมัติล่าสุด
